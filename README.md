# micro:bit V2 Web Bluetooth 테스트

BBC micro:bit V2의 기존 MakeCode UART 펌웨어에서 데이터를 받는 최소 정적 웹사이트입니다. 펌웨어는 변경하지 않습니다. 프레임워크, npm 의존성, 빌드, 백엔드, 데이터 저장이 없습니다.

## 실행

`index.html`, `style.css`, `app.js`를 같은 위치에 배포합니다. 개발 PC에서는 저장소에서 `python3 -m http.server 8000 --bind 127.0.0.1`로 실행하고 localhost에서 확인할 수 있습니다. 스마트폰의 Bluetooth 테스트는 아래 GitHub Pages HTTPS 주소에서 진행하세요. 스마트폰에서 PC의 HTTP IP 주소로 접속하면 Web Bluetooth를 사용할 수 없습니다.

선택적 개발 검증: Node.js가 있으면 `node --check app.js`와 `node --test tests/bluetooth.test.cjs`를 실행합니다. 모의 GATT 테스트는 실제 무선 연결 성공을 입증하지 않습니다.

## GitHub Pages 배포

1. 변경 커밋을 GitHub `main` 브랜치에 push합니다.
2. 저장소 Settings → Pages → Build and deployment에서 **Deploy from a branch**를 선택합니다.
3. Branch를 **main**, 폴더를 **/(root)**로 지정하고 Save합니다.
4. 배포 완료 후 `https://soup-bean.github.io/microbit-study-web/`를 Android Chrome에서 엽니다. 실제 배포 상태와 주소는 Pages 설정 화면에서 확인하세요.

별도 빌드나 Actions workflow 파일은 필요하지 않습니다.

## 통신 사양

| 역할 | UUID | 속성 |
| --- | --- | --- |
| UART 서비스 | `6e400001-b5a3-f393-e0a9-e50e24dcca9e` | 서비스 |
| micro → 웹 수신 | `6e400002-b5a3-f393-e0a9-e50e24dcca9e` | INDICATE |
| 웹 → micro 송신 | `6e400003-b5a3-f393-e0a9-e50e24dcca9e` | WRITE / WRITE NO RESPONSE |

서비스 필터와 optionalServices를 지정하여 기기를 요청합니다. 수신 특성에 startNotifications()를 호출합니다. 이번 단계에서는 송신 특성을 사용하지 않습니다.

UTF-8 스트리밍 디코더로 바이트 분할을 처리하고 LF 또는 CRLF로 끝난 메시지를 표시합니다. 한 조각의 여러 줄과 조각 사이에 나뉜 CRLF도 처리합니다. 줄바꿈 없는 수신은 시간·바이트 수·문자열을 조각 로그에 남기지만 최신 완성 메시지에는 반영하지 않습니다. CR 단독은 구분자가 아닙니다. 완성되지 않은 버퍼는 연결 해제 시 폐기하며, 8,192자 초과 시에도 폐기합니다. 로그는 최근 300건만 메모리에 유지하고 새로고침하면 사라집니다.

## 실제 스마트폰 테스트 체크리스트 (미실행)

1. Android Bluetooth를 켜고, micro:bit 전원을 켭니다. 기존 MakeCode 펌웨어 및 No Pairing Required 설정을 유지합니다.
2. nRF Connect 등 다른 앱의 micro:bit 연결을 해제합니다.
3. Android Chrome에서 Pages HTTPS 주소를 열고 **Bluetooth 연결**을 누릅니다.
4. micro:bit를 선택하고 **연결 성공**을 확인합니다.
5. B 버튼을 누르고 큰 수신값에 `READ:240`, 로그에 수신 시각과 내용이 표시되는지 확인합니다.
6. B 버튼을 여러 번 눌러 수신 누락·중복·지연을 관찰합니다. 줄바꿈이 없다면 조각 로그를 확인합니다.
7. **연결 해제** 후 다시 연결하고 B 버튼 수신을 확인합니다.
8. 보드 전원을 껐다 켜서 연결 해제 표시, 재연결, 저장된 `READ:240` 수신을 확인합니다.
9. 선택 창 취소 및 브라우저 권한 거부 후 재시도가 가능한지 확인합니다. 화면 잠금·백그라운드 전환 후에도 상태와 재연결을 확인합니다.

## 제약 및 오류 진단

- Android Chrome과 HTTPS가 필요합니다. iOS Safari 등 Web Bluetooth 미지원 브라우저에서는 연결할 수 없습니다.
- 기기가 검색되지 않으면 서비스 UUID 광고 여부, 전원, 거리, 다른 앱의 점유 상태를 확인하세요. 서비스 필터와 맞는 기기만 표시합니다.
- 권한/보안 오류, 선택 취소, GATT 연결, 서비스 검색, 특성 검색, 알림 설정 오류를 구분해 표시합니다. Android 버전에 따라 Bluetooth/주변 기기 등의 OS 권한도 확인해야 합니다.
- 자동 재연결은 하지 않습니다. 사용자가 연결 버튼으로 다시 선택합니다. 재연결 시 최신 수신값과 미완성 버퍼를 초기화합니다. 해제 후 남아 있는 최신값은 이전 세션 값입니다.
- OS 절전, 화면 잠금, 전파 간섭에 따른 연결·수신 안정성은 실제 장비에서 검증해야 합니다. 앱은 통신 로그를 영구 저장하지 않습니다.
- 현재 검증은 로컬 정적 파일 응답과 모의 GATT 테스트에 한정됩니다. 실제 Android/micro:bit 통신 및 GitHub Pages 배포 성공은 확인되지 않았습니다.


## RTC 시간 동기화 (2단계 실험)

- firmware/rtc-sync-test.ts의 MakeCode 코드를 새 프로젝트에 붙여 넣고 Bluetooth, FlashStorage, DS1302 확장을 추가합니다.
- MakeCode Project Settings에서 **No Pairing Required**를 활성화합니다.
- 마이크로비트 RTC 배선: VCC→3.3V, GND→GND, CLK→P13, DAT→P14, RST→P15.
- 웹사이트에서 Bluetooth를 연결하면 **RTC 시간 동기화** 버튼이 활성화됩니다.
- 사용자가 직접 버튼을 누르면 현재 휴대폰 시각을 **Asia/Seoul (UTC+9)** 기준으로 전송합니다.
- 장치가 \`SYNC:OK\`를 보내면 웹에 완료 표시가 나타납니다. B 버튼을 누르면 \`DATE:\`, \`TIME:\` 메시지로 보정 결과를 확인합니다.
- UART 송신 특성: 6e400003-b5a3-f393-e0a9-e50e24dcca9e (WRITE/WRITE WITHOUT RESPONSE).
- 명령 형식: \`T:YYYYMMDDHHMMSSW\n\` (총 18 ASCII bytes, 요일은 일=1…토=7).
- 아직 오전 5시 날짜 경계 처리, 학습시간 누적, IndexedDB 저장은 구현하지 않았습니다.
- **보안**: No Pairing Required는 근처의 다른 BLE 클라이언트도 연결 및 UART 명령 전송을 시도할 수 있습니다. 시험 환경에서만 사용하고 최종 배포 시 페어링/권한 설계를 재검토하세요.


## RTC 기준 오전 5시 학습일 및 7일 기록 시험 (3단계)

**MakeCode 펌웨어:** [firmware/study-day-test.ts](firmware/study-day-test.ts)

준비: 기존 통합 프로젝트를 복제하고 Bluetooth / FlashStorage / DS1302 확장을 유지합니다. MakeCode 설정에서 **No Pairing Required**를 켜고, RTC CLK=P13 / DAT=P14 / RST=P15 / 3.3V / GND 배선은 그대로 둡니다. 시험 전 웹사이트에서 RTC 시간 동기화가 정상인지 다시 확인하세요.

### 버튼과 웹 명령

- A: 현재 *공부 날짜*에 **300초(5분) 추가**하고 즉시 FlashStorage 저장. 이는 실제 공부 자동 측정이 아닌 시험용 수동 증가입니다.
- A+B: **60초(1분) 추가**하고 저장.
- B: RTC 날짜·시간, 학습 날짜, 최근 7일 누적 기록을 BLE로 전송.
- 웹의 **저장 기록 가져오기**: UART `R\n` 명령으로 B 버튼과 같은 데이터를 요청.
- 웹의 **RTC 시간 동기화**: 기존 `T:YYYYMMDDHHMMSSW\n` 형식을 유지합니다.
- 웹 고급 메뉴 **RTC를 04:59:30으로 설정**: UART `X\n` 명령. 실제 RTC 시각을 일시적으로 04:59:30으로 변경합니다. 반드시 시험 후 실제 한국 시각으로 다시 동기화해야 합니다.

공부 날짜 = RTC의 한국 날짜에서 **05:00 이전이면 하루 전 날짜**. 05:00 이후엔 실제 날짜. 월말·연말·윤년 이전 날짜 계산을 포함합니다. 오전 5시 전환은 RAM에서 자동 반영하며 FlashStorage 저장은 A/A+B 버튼을 눌렀을 때만 수행합니다.

**FlashStorage 수정:** 현재 micro:bit V2 MakeCode 런타임은 키-값 쌍 최대 **5개** 제한이 있으므로, 기존 `D0`~`D6`의 7개 슬롯 설계를 사용하지 않습니다. 수정된 펌웨어는 키 `H` **하나**에 최신 기록 날짜(YYMMDD, 6자리)와 **최근 7일의 초 단위 누적값**을 각각 3글자의 64진 압축 문자로 기록합니다. `YYMMDD|` + 21글자 + `|` + NUL로 **총 30바이트**, 키 1개·값 최대 32바이트 규격을 만족합니다. 날짜별 누적값을 갱신하고 7일보다 오래된 기록은 새 날짜의 기록을 추가하면서 밀려납니다. 최근 7일 밖의 기록은 BLE 전송 대상이 아닙니다. 장기 저장은 향후 IndexedDB 백업이 필요합니다. 펌웨어 재다운로드 시 플래시 기록은 지워질 수 있습니다.

**이전 시험 데이터 처리:** 새 펌웨어 첫 시작 시 `H`가 없으면 기존 시험용 `D0`~`D6` 데이터를 읽어 복원 가능한 최근 기록을 `H`로 이전하려고 시도합니다. 그런 다음 오래된 **시험용 키** `D0`~`D6`, `test_value`, `rtc_combo`를 삭제해 저장 공간을 확보합니다. 이는 기존 시험 데이터에 대한 변경이므로 중요한 값이 있다면 먼저 웹사이트 로그를 기록해 두세요. 펌웨어 재업로드 자체로 기존 값이 삭제되면 이전은 불가능합니다. 기타 시스템 키는 건드리지 않습니다.

### BLE 기록 형식

- `DATE:2026-11-15`, `TIME:20:30:00` — RTC 시각
- `BEGIN:20261115` — 현재 공부 날짜 및 새 스냅샷 시작
- `REC:20261114:300` — 날짜별 누적 초 (누적 덮어쓰기, 델타 아님)
- `REC:20261115:0` — 오늘 기록이 없으면 표시용 0초 전송
- `END:2` — 보내진 날짜 수, 웹사이트는 개수 일치 시에만 표 갱신

`REC` 메시지는 줄바꿈 포함 최대 20바이트가 되도록 초를 0~86400으로 제한합니다. 웹은 날짜별로 **대체** 표시하므로 여러 번 요청해도 중복 더해지지 않습니다. 현재 웹에서 받은 데이터는 **일시적인 표시만 가능**하며 새로고침하면 사라집니다. 외부 서버에 전송하지 않습니다.

### 실제 통합 검증

1. MakeCode 새 코드 다운로드 후 Android Chrome에서 웹사이트에 연결. 먼저 RTC 시간 동기화를 완료합니다.
2. A 1회 (+300초), A+B 1회 (+60초), B 또는 **저장 기록 가져오기**를 눌러 해당 학습일이 `00h 06m 00s`인지 확인합니다.
3. 전원 완전 차단 후 재연결하고 B/기록 요청을 반복합니다. 같은 날짜의 360초가 복원되면 성공입니다.
4. 고급 메뉴에서 **RTC를 04:59:30으로 설정** 후 즉시 A를 1회 누르고 기록 요청하여 '전날' 기록에 300초가 추가되는지 확인합니다. 05:00을 지날 때까지 기다린 뒤 A를 눌러 '오늘' 기록이 별도 누적되는지 확인합니다. 이미 같은 날짜에 시험 기록이 있었다면 총합은 달라질 수 있습니다.
5. 끝나면 반드시 **RTC 시간 동기화** 버튼을 다시 누르고 B로 DATE/TIME을 확인합니다.
6. B/기록 요청을 반복하여 같은 날짜가 중복 합산되지 않는지 확인합니다.

**중요:** 이번 버전은 센서를 이용한 자동 공부시간 측정, 주기적 자동 저장, 장기 웹 저장/백업 기능이 없습니다. 실제 공부 데이터를 기록하지 않는 **시험 전용 펌웨어**입니다. 저장 키는 이전 `rtc_combo`와 분리되어 있습니다. 7일 이상 스마트폰 연결이 없어도 무제한 보존되는 구조가 아니므로 본 프로젝트 최종 버전에는 데이터 내보내기·ACK 동기화·장기 보관을 추가해야 합니다.

소프트웨어 테스트 `node --test tests/*.test.cjs`는 웹 JavaScript와 날짜 계산 참조 구현만 검증하며, 실제 MakeCode 컴파일 및 RTC·BLE 하드웨어 작동을 증명하지 않습니다.

## 자동 공부 시간 측정 v1 — RTC·FlashStorage·BLE·센서 통합

**MakeCode 전체 코드:** [firmware/auto-study-time-v1.ts](firmware/auto-study-time-v1.ts)

기존 프로젝트와 별도의 시험용 펌웨어입니다. MakeCode의 Bluetooth, FlashStorage, DS1302 확장을 추가하고 **No Pairing Required** 설정을 유지하세요. JavaScript 편집기를 사용하며 블록으로 변환하지 마세요.

### 배선

| 장치 | 배선 |
| --- | --- |
| DS1302 | CLK=P13, DAT=P14, RST=P15, 3.3V, GND |
| HC-SR04 | TRIG=P1, ECHO→10kΩ 3개 분압→P2, VCC=5V, GND |
| HC-SR501 | OUT=P8, VCC=5V, GND |

초음파 분압: 센서 ECHO→빵판 15번→10kΩ→12번(P2)→10kΩ→13번→10kΩ→14번(GND). **센서의 5V ECHO를 P2에 직접 연결하지 마세요.** 모든 GND는 공통이며 기존 검증된 배선을 유지합니다.

### 상태 판정 및 공부 시간

- PIR을 약 3초마다 읽고 **200ms 후** 초음파 거리 측정. 거리 10~60cm를 정상 범위로 사용.
- **HERE:** 거리 정상, PIR 0 연속 3회 미만 → 공부 시간 누적.
- **STILL:** 거리 정상, PIR 0 연속 3회 이상 → 움직이지 않아도 누적.
- **WAIT:** 거리 범위 밖이지만 아직 AWAY 확정 전 → 누적 보류. HERE/STILL로 복귀하면 보류 구간 합산.
- **AWAY:** 거리 범위 이탈 연속 3회 + PIR 0 연속 3회 + 처음 60초 안정화 완료 → 보류 구간 폐기, 공부 시간 중단.
- 전원을 켠 직후의 미확인 WAIT 구간은 누적하지 않음. RTC가 휴대폰 동기화로 점프해도 점프 간격을 누적하지 않음.
- RTC **오전 5시**에 공부 날짜 전환. 전환 시각을 가로지르는 짧은 구간은 날짜별로 분리해 기록.
- HC-SR04는 사람을 직접 인식하지 않으므로 책·의자 등이 범위에 있으면 잘못된 사용자 존재 판정이 가능함.

### 버튼, 기록 및 저장

- **A:** 현재 HERE/STILL/WAIT/AWAY 상태 및 거리·PIR·연속 미감지 횟수 확인 (조회 전용).
- **B:** Bluetooth 연결 시 저장 후 7일 기록 전송; 비연결 시 저장 후 오늘 누적 초 표시.
- **A+B, A를 통한 +300초 등의 수동 공부 시간 추가 기능은 없음.**
- 웹의 기존 기록 요청 R, RTC 동기화 T, 경계 시험 X 명령은 유지. 웹 기록은 스냅샷 대체 표시로 중복 합산되지 않음.
- 최근 7일 기록을 FlashStorage의 기존 단일 키 H(30바이트)에 보존. **공부 중에는 5분 간격**, AWAY 전환 또는 B/웹 기록 요청 시 저장 시도.
- **주의:** 전원이 갑자기 끊기면 가장 최근 약 5분의 미저장 공부 시간이 손실될 수 있음. 장기간 사용 전 Flash 쓰기 내구성과 저장 간격 재검토 필요.
- 이전 수동 시험 기록이 남아 있다면 자동 누적값에 합쳐질 수 있음. 펌웨어 재업로드 시 Flash 기록이 지워질 수 있음.
- 웹사이트 장기 저장(IndexedDB 등)은 아직 없음. 기기 기록은 최근 7일 범위.

### 실제 통합 시험

1. 이전 검증된 MakeCode 프로젝트를 보관하고 이 코드를 새 프로젝트에 업로드. 웹에서 RTC 시간 동기화(SYNC:OK).
2. 15~30cm에서 HERE→STILL을 확인하며 30~60초 머문 후 B/웹 기록 요청. **자동으로 초가 늘었는지** 확인.
3. 잠깐 범위를 벗어나 WAIT 뒤 HERE로 복귀: 짧은 WAIT 시간 합산 확인.
4. 센서 앞을 비우고 PIR 감지 영역에서 벗어나 WAIT→AWAY: 해당 WAIT 제외·누적 중지 확인.
5. B/웹 기록 요청으로 저장한 뒤 전원을 끄고 다시 켜서 기록 복원 확인.
6. 05시 경계 시험은 시간과 실제 기록을 변경하므로 별도 실험 중에만 사용하고 완료 후 RTC를 실제 한국 시각으로 재동기화.

**검증 범위:** 기존 RTC/BLE/Flash, 센서 동시 사용, 상태 판정은 각각 실제 장비에서 확인되었음. **새 자동 누적 통합 파일 자체의 MakeCode 컴파일과 실물 동작은 아직 미검증**. 날짜 경계·WAIT 처리 등은 JavaScript 참조 모델로 검증.


## v1.1 — 자세 변화에 대한 판정 안정화

**추천 시험용 코드:** [firmware/auto-study-time-v1.1.ts](firmware/auto-study-time-v1.1.ts). 아래 변경만 적용했으며 v1 원본과 RTC, FlashStorage 형식, BLE 프로토콜, 배선 및 약 3초 측정 순서는 보존합니다.

- 진입 10~60cm, 이미 감지된 사용자는 10~80cm 범위에서 유지. AWAY 확정 후에는 다시 10~60cm가 필요합니다.
- 거리 이탈 첫 번째: 표시 상태 HERE/STILL 유지, 첫 실패 측정 시점부터 보류. 그 이전 마지막 정상 측정 이후의 구간은 기존처럼 공부 시간으로 계산합니다.
- 이탈 두 번째부터 WAIT. 이탈 연속 5회와 PIR 0 연속 3회가 모두 성립하면 AWAY (초기 안정화 60초 이후).
- 복귀 시 보류한 구간을 한 번만 합산하며 AWAY 확정 시 폐기. 기존 v1과 같이 60초를 초과하는 미해결 보류 구간은 합산하지 않습니다.
- USB 시리얼에 HOLD:1/0을 추가해 표시 상태가 H/S여도 누적 보류 여부를 확인할 수 있습니다.
- A는 상태 확인, B는 기록 전송/저장/조회. 수동 시간 추가 기능 없음.

실제 판정 함수의 모의 하드웨어 시험 8개 통과: 진입/유지 거리, 한 번 이탈과 복구, 두 번째 WAIT·다섯 번째 AWAY, 80cm 복귀, PIR 연속 조건, 초기 WAIT, RTC 점프, 60초 초과 보류. 실제 MakeCode v1.1 컴파일 및 하드웨어 시험은 아직 수행하지 않았습니다.

실물 시험: (1) 20~30cm에서 시작해 70cm로 이동하여 HERE/STILL 유지 확인, (2) 거리 범위 밖 1회 후 원위치 복귀, (3) 80cm 초과/NO와 PIR 0이 유지되는 상태에서 WAIT→AWAY 확인, (4) AWAY 확정 후 70cm에서는 재개하지 않고 60cm 이내에서 재개하는지 확인. 날짜별 기록을 조회하고 전원을 완전히 껐다 켜서 저장 복원도 확인합니다.
